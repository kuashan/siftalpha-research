## 2. Research objective

Develop a Discovery-only economic map for a native 15-minute BTC dynamic position engine.

E035 must answer:

1. Which fixed 15m structural tempo produces a usable baseline lifecycle?
2. Where do distinct OPEN modes appear?
3. During an open lifecycle, where is incremental ADD exposure economically attractive?
4. Where does partial REDUCE have positive price advantage versus holding to the baseline close?
5. After pre-defined risk markers, where do recovery events have positive RE-ADD economics?
6. Where would an earlier CLOSE improve economics versus the baseline close?
7. Does the opportunity survive realistic 15m trading costs?

E035 cannot validate production actions.

Any exact OPEN / ADD / REDUCE / RE-ADD / CLOSE trigger inspired by E035 requires E036 or later.

## 7. Baseline OPEN / CLOSE semantics

For Phase A only, preserve the existing structural semantics using each configuration's own parameters.

Qualified GRB OPEN:

EffectiveState = GREEN
AND H > FastUpper
AND REF(H,1) <= REF(FastUpper,1)
AND dsep > 0
AND C >= WhiteLower - 2 * ATR

Execute next 15m open.

Failure close:

before first Effective Red:
Effective Gray -> Effective Green
then close next 15m open.

Mature close:

after first Effective Red:
Effective Red -> Effective Gray
then close next 15m open.

One baseline lifecycle at a time.

- maximum favorable excursion

### Phase A baseline eligibility

A configuration is eligible only if:

- at least 20 resolved lifecycles;
- at least 4 Failure lifecycles;
- at least 1.5 resolved lifecycles per 30 days;
- median hold >= 8 bars;
- median hold <= 384 bars;
- base-friction median net return > 0;
- base-friction profit factor > 1.10;
- stress-friction mean net return > 0.

### Baseline selection

Among eligible configurations:

1. highest base-friction median net return;
2. if medians differ by <= 0.10 percentage points, higher base-friction PF;
3. then lower top-3 winner concentration;
4. then higher resolved lifecycle count.

If no configuration is eligible:
E035 stops with NO_15M_BASELINE and Phase B is not opened.

## 9. Phase B — full dynamic action opportunity map

### 9.1 OPEN opportunity families

Only when baseline engine is FLAT.

Exactly four formal event families:

#### O1 — GRB
The selected baseline's Qualified GRB.

#### O2 — FAST_BREAKOUT
EffectiveState = GREEN
AND H > FastUpper
AND REF(H,1) <= REF(FastUpper,1)

No dsep or PriceNearWhite requirement.

#### O3 — GREEN_TRANSITION
EffectiveState changes from non-GREEN to GREEN.

#### O4 — FASTMID_RECLAIM
EffectiveState = GREEN
AND REF(C,1) <= REF(FastMid,1)
AND C > FastMid

For each event:
signal after close -> hypothetical entry next open.

Exit uses the same selected-baseline lifecycle semantics:
- if Effective Red occurs after entry, next Red->Gray close;
- otherwise first Gray->Green close.

For anti-pseudoreplication:
primary OPEN view counts only the first occurrence of each event family per Effective Green episode.

OPEN family metrics:
- events
- resolved
- gross / base-net / stress-net return
- median
- q25
- PF
- win rate
- median hold
- top-3 positive-return concentration
- MFE / MAE

OPEN candidate-zone gate:
- >= 20 resolved events
- base-net average > 0
- base-net median > 0
- base-net PF > 1.25
- stress-net median >= 0
- q25 > -2.0%
- top-3 gross-positive share <= 60%

A passing OPEN family is only a Discovery candidate.

Only inside selected-baseline resolved lifecycles.

At every causally available decision bar before the official baseline close:

hypothetical ADD:
decision after bar close
-> add one equal unit next bar open
-> exit added unit at the same official baseline final close.

Base and stress friction apply to the added unit.

Primary counting:
first entry per baseline lifecycle per map cell.

Exactly four formal maps:

A1. phase x bars since original entry
- PRE_RED / POST_RED
- B00_07 / B08_31 / B32_95 / B96P

A2. CurrentProgressATR x GivebackATR
Progress:
- P_LE_0
- P_0_1
- P_1_2
- P_GT_2
Giveback:
- G_LT_05
- G_05_1
- G_1_2
- G_GE_2

A3. RunningMFEATR x CurrentProgressATR
MFE:
- M_LT_1
- M_1_2
- M_2_4
- M_GE_4
using the same progress bins.

A4. EffectiveState x dsep sign x FastBand location
State:
GREEN / GRAY / RED / OTHER
dsep:
POS / NONPOS
FastBand location:
BELOW_MID / MID_TO_UPPER / ABOVE_UPPER

ADD candidate-zone gate:
- >= 20 first-entry lifecycle events
- base-net average > 0
- base-net median > 0
- base-net PF > 1.25
- stress-net median >= 0
- q25 > -2.0%
- top-3 gross-positive share <= 60%

Report at most top 10 ADD zones by:
median, then PF, then count.

### 9.3 REDUCE opportunity maps

At every in-position decision bar before official baseline close:

hypothetical REDUCE one unit next bar open.

Reduction edge:

net proceeds from reducing next open
minus
net proceeds from holding that unit to official final close,

expressed as percentage advantage relative to the next-open reduction price.

Positive edge means reducing earlier was economically better for that unit.

Primary:
first entry per lifecycle per map cell.

Exactly three maps:

R1. phase x RunningMFEATR x GivebackATR

R2. EffectiveState x dsep sign

R3. price location
- BELOW_FASTMID
- FASTMID_TO_FASTUPPER
- ABOVE_FASTUPPER
x fast-width change over 5 bars
- WIDTH_UP
- WIDTH_NONUP

REDUCE candidate-zone gate:
- >= 15 lifecycle events
- median reduction edge > +0.15%
- mean reduction edge > 0
- >= 60% positive reduction-edge events
- top-3 edge contribution <= 70%

Report at most top 10 zones.

### 9.4 RE-ADD recovery map

E035 does not assume any REDUCE trigger is validated.

It defines three generic risk markers only for diagnostic recovery mapping:

K1:
RTE candidate event.

K2:
EffectiveState changes GREEN -> GRAY while in position.

K3:
C crosses from >= FastMid to < FastMid while in position.

After each first risk marker occurrence in a lifecycle, exactly three formal recovery events are mapped:

RA1:
dsep crosses from <= 0 to > 0.

RA2:
C crosses from <= FastMid to > FastMid.

RA3:
EffectiveState changes GRAY -> GREEN.

Hypothetical RE-ADD:
next open after recovery
-> exit at same official baseline close.

Do not require that a real reduction actually occurred.

RE-ADD candidate gate:
- >= 15 resolved recovery events
- base-net average > 0
- base-net median > 0
- PF > 1.25
- stress-net median >= 0
- median recovery execution price not more than 1 EntryATR above the risk-marker execution-equivalent price

This is diagnostic only.

### 9.5 CLOSE opportunity maps

At every in-position decision bar before official baseline close:

hypothetical CLOSE:
close entire unit next bar open.

Close edge:

net proceeds from closing next open
minus
net proceeds at official baseline final close,

expressed as percentage advantage relative to next-open close price.

Positive means earlier full close would have been better.

Primary:
first entry per lifecycle per map cell.

Exactly three maps:

C1. EffectiveState transition
- GREEN_TO_GRAY
- GRAY_TO_GREEN
- GREEN_TO_RED
- RED_TO_GRAY
- OTHER

C2. RunningMFEATR x GivebackATR

C3. dsep sign x price location relative to FastMid / FastLower

CLOSE candidate-zone gate:
- >= 15 lifecycle events
- median close edge > +0.20%
- mean close edge > 0
- >= 60% positive close-edge events
- for any mature-path candidate, must not remove more than 40% of the later remaining MFE on median

Report at most top 10 zones.
