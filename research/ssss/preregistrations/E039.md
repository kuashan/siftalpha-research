## 2. User-requested action architecture

Starter OPEN:
30% of account equity.

ADD type 1 — TREND_ADD:
model estimates future upside probability is high while current position is not losing.

Size:
+10 percentage points of account equity.

ADD type 2 — LOSS_ADD:
position is already losing by at least a data-selected loss threshold,
but model still estimates future upside probability is high.

Size:
+10 percentage points of account equity.

Maximum account exposure:
50%.

REDUCE type 1 — PROFIT_RISK_REDUCE:
position is profitable,
continuation probability remains high,
but near-term drawdown probability is high.

Size:
sell 15% of CURRENT POSITION QUANTITY.
Example:
40% exposure -> approximately 34%.
50% exposure -> approximately 42.5%.

REDUCE type 2 — LOSS_RISK_REDUCE:
position is losing,
continuation probability is no longer high but is not decisively bearish,
and near-term drawdown probability is high.

Size:
sell 15% of current position quantity.

Existing reference CLOSE remains unchanged.

## 5. Probability model

Model family:
regularized logistic regression.

No tree model, neural network, boosting, or model-family search.

Two models:

### P_UP

Target at decision bar t:

1 if a hypothetical +10% incremental unit entered at next bar open
and exited at the existing reference CLOSE
has positive net return after base friction.

0 otherwise.

### P_DD4H

Target at decision bar t:

1 if, within the next 16 x 15m bars (4 hours), or before reference close if sooner,
the future low reaches at least 1.0 current ATR below the next-open execution price.

0 otherwise.

This is a near-term drawdown-risk probability.

## 7. Chronological out-of-fold protocol

Resolved starter lifecycles are ordered by entry time.

First 15 lifecycles:
training seed only.

Then four expanding walk-forward blocks:

- train first 15 -> predict next 8 lifecycles
- train first 23 -> predict next 8
- train first 31 -> predict next 8
- train first 39 -> predict remaining resolved lifecycles

Training rows from each lifecycle are weighted so each lifecycle contributes equal total weight.

No predicted row may use a model trained on that lifecycle or any later lifecycle.

Only out-of-fold probabilities may determine action thresholds.

Final Discovery model may be refit on all Discovery lifecycles only AFTER thresholds are frozen for later OOS use.

## 10. Action definitions

All actions execute next 15m open.

### TREND_ADD

Current position return >= 0
AND P_UP >= high-upside threshold
AND P_DD4H < high-drawdown threshold.

Action:
+10 percentage points exposure,
subject to 50% cap.

### LOSS_ADD

Current position return <= selected negative loss threshold
AND P_UP >= high-upside threshold
AND P_DD4H < high-drawdown threshold.

Action:
+10 percentage points exposure,
subject to 50% cap.

### PROFIT_RISK_REDUCE

Current position return > 0
AND P_UP >= high-upside threshold
AND P_DD4H >= high-drawdown threshold.

Action:
sell 15% of current position quantity.

### LOSS_RISK_REDUCE

Current position return < 0
AND P_UP >= 0.45
AND P_UP < high-upside threshold
AND P_DD4H >= high-drawdown threshold.

Action:
sell 15% of current position quantity.

Reference CLOSE overrides all sizing actions.

## 11. Action de-duplication

Each condition acts only on transition from FALSE -> TRUE.

After an action:
minimum cooldown = 4 bars / 1 hour.

A condition must become FALSE before the same action type can re-arm.

This prevents repeated action every 15 minutes while the same state persists.

## 12. Threshold selection objective

Discovery thresholds are selected from the frozen grids using only OOF predictions.

Primary ranking is portfolio-level net return improvement versus:

30% starter
+ existing E037 first-ADD benchmark only
+ reference CLOSE.

But a threshold set is eligible only if:

- at least 15 total probability-driven actions;
- at least 5 actions from at least two distinct action types;
- net return improvement > 0;
- maximum drawdown does not worsen by more than 10% relative;
- Mature-path total PnL is not reduced by more than 10%;
- stress-friction total PnL improvement >= 0;
- no single lifecycle contributes >35% of incremental PnL.

Tie-break:
1. higher stress-friction incremental PnL;
2. lower turnover;
3. lower max drawdown.

## 13. LOSS_ADD threshold interpretation

The selected loss threshold must additionally have:

- >= 8 LOSS_ADD events;
- positive average incremental 10% unit return;
- positive median incremental return;
- base PF > 1.25;
- stress median >= 0;
- q25 > -2.5%.

If none pass:
LOSS_ADD_THRESHOLD_NOT_FOUND.

No loss threshold is written into the research model as active if this gate fails.

Recorded before any E039 model outcome was inspected.

For both P_UP and P_DD4H:

- numeric features are standardized using TRAINING rows only;
- the intercept is not regularized;
- L2 penalty lambda = 0.10;
- optimizer = deterministic full-batch gradient descent;
- iterations = 120;
- learning rate = 0.08;
- lifecycle-equal weighting is applied:
  each lifecycle contributes total training weight 1.0 regardless of its number of 15m decision rows;
