## 5. Phase A — four OPEN modes

All modes are evaluated only after B2 warmup.

Signal after completed 15m close.
Execution next 15m open.

### O1 — GRB

EffectiveState = GREEN
AND H > FastUpper
AND REF(H,1) <= REF(FastUpper,1)
AND dsep > 0
AND C >= WhiteLower - 2*ATR

### O2 — FAST_BREAKOUT

EffectiveState = GREEN
AND H > FastUpper
AND REF(H,1) <= REF(FastUpper,1)

No dsep / PriceNearWhite requirement.

### O3 — GREEN_TRANSITION

EffectiveState changes:
non-GREEN -> GREEN.

### O4 — FASTMID_RECLAIM

EffectiveState = GREEN
AND REF(C,1) <= REF(FastMid,1)
AND C > FastMid

## 6. OPEN lifecycle labeling

Each OPEN mode is evaluated independently first.

Primary counting:
first occurrence of that OPEN mode per Effective Green episode.

Entry:
next 15m open.

Exit semantics after entry:

If Effective Red occurs after entry:
first Effective Red -> Effective Gray transition,
exit next 15m open.

If no Effective Red occurs:
first Effective Gray -> Effective Green transition,
exit next 15m open.

If no exit occurs before Discovery end:
unresolved and excluded from return metrics.

## 8. Multi-Open Reference construction

Requires at least TWO OPEN modes to pass.

All passing modes are enabled.

When FLAT:
the chronologically first passing-mode signal opens the position.

If multiple passing modes fire on the same bar, fixed reason priority is:

1. O1_GRB
2. O2_FAST_BREAKOUT
3. O4_FASTMID_RECLAIM
4. O3_GREEN_TRANSITION

Once position is open:
other OPEN signals are ignored until flat again.

Exit uses the B2 lifecycle close semantics.

For each executed OPEN record:
- primary mode_id
- all same-bar mode tags
- entry/exit
- path
- costs
- MFE/MAE

Multi-Open Reference gate:

- >= 30 resolved lifecycles
- >= 2 distinct OPEN mode IDs with at least 10 executed entries each
- base-net mean > 0
- base-net median > 0
- base PF > 1.25
- stress-net mean > 0
- stress-net median >= 0
- q25 > -2.0%
- top-3 positive share <= 60%

If this gate fails:
E036 stops with NO_MULTI_OPEN_REFERENCE.

### 9.1 ADD

At every in-position decision bar before reference close:

hypothetical +1 unit next open
-> exit added unit at same reference close.

A3 RunningMFEATR x CurrentProgressATR:
M_LT_1 / M_1_2 / M_2_4 / M_GE_4
x same progress bins

A4 EffectiveState x dsep sign x FastBand location:
GREEN/GRAY/RED/OTHER

### 9.3 RE-ADD

Risk markers:

K1 RTE
K2 GREEN -> GRAY
K3 close crosses below FastMid

After first marker in lifecycle, recovery events:

RA1 dsep <=0 -> >0
RA2 close <=FastMid -> >FastMid
RA3 GRAY -> GREEN

Hypothetical re-add:
next open after recovery
-> reference final close.

Gate:
- >=15 resolved recoveries
- base mean >0
- base median >0
- PF >1.25
- stress median >=0
- median re-add execution <= risk-marker-equivalent price + 1 EntryATR

### 9.4 CLOSE

Hypothetical full close next open.

next-open exit proceeds vs reference final-close proceeds.

GREEN_TO_GRAY / GRAY_TO_GREEN / GREEN_TO_RED / RED_TO_GRAY / OTHER

ABOVE_FASTMID / FASTMID_TO_FASTLOWER / BELOW_FASTLOWER

Gate:
- >=15 lifecycle events
- median close edge > +0.20%
- mean >0
- >=60% positive edge
- mature-path candidates may not remove >40% of later remaining MFE on median

Top 10 max.
