# E032 Pre-registration — ADD Opportunity Map

Date: 2026-09-19
Status: PRE-REGISTERED
Category: ADD diagnostic research

## Research question

Where inside a validated SSSS trade does an incremental unit actually have positive marginal value if it is added at the next open and held to the official final CLOSE?

E032 reverses the previous workflow.

Instead of proposing a technical ADD trigger first, E032 maps the realized marginal economics of every causally available in-trade decision bar in Discovery and asks which pre-defined time / price / structure regions consistently contain positive incremental-return opportunities.

E032 is a Discovery-only diagnostic round.

It cannot validate or accept an ADD trigger.

Any specific trigger inspired by E032 requires a new Experiment ID and new pre-registration before OOS.

## Eligible trades

Only official SSSS trades with a resolved official CLOSE execution are used for return mapping.

OPEN:
Qualified GRB signal at close, execute next tradable open.

CLOSE:
- Failure path: Effective Gray -> Effective Green, execute next open.
- Mature path: Effective Red -> Effective Gray, execute next open.

Unresolved trades are excluded from return-to-final-CLOSE statistics because the terminal value is unknown.

## Hypothetical ADD opportunity definition

For each resolved trade, examine every decision bar t satisfying:

- t is on or after the original OPEN execution bar;
- t is strictly before the official CLOSE signal bar;
- t+1 exists and is strictly before or equal to the official CLOSE execution bar.

Assume:
- ADD decision known after close of t;
- ADD executes at open of t+1;
- ADD exits at the same official final CLOSE execution open as the original position;
- transaction cost = 0.1% on ADD entry and 0.1% on ADD exit.

Define:

```text
ADD_return(t)
=
(final_close_open * 0.999)
/
(next_open_after_t * 1.001)
- 1
```

This is a diagnostic label, not a production action.

## Fixed causal features at decision bar t

All feature values must use information available by close of t only.

### Lifecycle phase

- PRE_RED: no Effective Red has occurred yet in the current trade
- POST_RED: Effective Red has already occurred

### Bars since original entry

Buckets:
- B00_04: 0-4 bars
- B05_09: 5-9
- B10_19: 10-19
- B20_39: 20-39
- B40P: 40+

### Current progress in EntryATR

```text
CurrentProgressATR = (C[t] - original_entry_open) / EntryATR
```

Buckets:
- P_LE_0: <= 0
- P_0_1: (0, 1]
- P_1_2: (1, 2]
- P_2_3: (2, 3]
- P_GT_3: > 3

### Running MFE in EntryATR

```text
RunningMFEATR
=
(max H from entry through t - original_entry_open) / EntryATR
```

Buckets:
- M_LT_1: < 1
- M_1_2: [1, 2)
- M_2_3: [2, 3)
- M_3_5: [3, 5)
- M_GE_5: >= 5

### Giveback from running high in EntryATR

```text
GivebackATR
=
(running_high - C[t]) / EntryATR
```

Buckets:
- G_LT_05: < 0.5
- G_05_1: [0.5, 1)
- G_1_2: [1, 2)
- G_GE_2: >= 2

### StructuralSep

```text
StructuralSep = (FastMid - WhiteMid) / WhiteWidth
```

Buckets:
- S_LT_0: < 0
- S_0_05: [0, 0.5)
- S_05_1: [0.5, 1)
- S_1_15: [1, 1.5)
- S_GE_15: >= 1.5

### Fast-band price location

- F_BELOW_MID: C < FastMid
- F_MID_UPPER: FastMid <= C <= FastUpper
- F_ABOVE_UPPER: C > FastUpper

### Effective state

- GREEN
- GRAY
- RED
- OTHER/NEUTRAL if present

### dsep sign

- D_POS: dsep > 0
- D_NONPOS: dsep <= 0

## Fixed opportunity maps

E032 will report exactly these five maps:

1. LifecyclePhase x BarsSinceEntry
2. CurrentProgressATR x GivebackATR
3. RunningMFEATR x CurrentProgressATR
4. StructuralSep x FastBandLocation
5. EffectiveState x dsepSign

No sixth map may be promoted into the formal E032 result after outcomes are viewed.

Additional raw descriptive statistics may be retained for audit, but they cannot be used to nominate the official E032 opportunity zones.

## Anti-pseudo-replication rule

Daily bars from the same trade are highly correlated.

Therefore E032 reports two views:

### All-bar view

Every eligible decision bar is included.

Purpose:
visualize the full economic surface.

### First-entry-per-trade view — PRIMARY

For each trade and each map cell, only the first decision bar on which that trade enters that cell is counted.

This is the primary view for opportunity-zone qualification.

A long trade therefore cannot dominate a map cell merely by remaining in that cell for many days.

## Metrics per map cell

Primary first-entry-per-trade metrics:

- event count
- unique trade count
- unique stock count
- win rate
- average net hypothetical ADD return
- median net hypothetical ADD return
- 25th percentile
- worst return
- profit factor
- top-3 winners as share of gross positive return
- Mature / Failure path counts
- median EntryATR distance of ADD execution from original entry
- median bars from entry to hypothetical ADD execution

Also report all-bar count / mean / median for context.

## Opportunity-zone qualification

A map cell is tagged CANDIDATE_ZONE only if all are true in the first-entry-per-trade view:

- at least 15 resolved trade events;
- at least 8 unique stocks;
- average net ADD return > 0;
- median net ADD return > 0;
- profit factor > 1.25;
- 25th percentile > -8%;
- top-3 winners <= 70% of gross positive return.

A cell that fails any condition is not a candidate zone.

Candidate zones are diagnostic only.

They are NOT validated ADD triggers.

## Ranking candidate zones

If multiple cells qualify, report at most the top 5 using:

1. highest median net ADD return;
2. if median differs by <= 0.25 percentage points, higher profit factor;
3. if still tied, larger unique-trade count.

Do not combine two or more cells into a new rule inside E032.

Any union/intersection/composite rule requires a new experiment.

## E032 stopping rule

E032 always stops after Discovery mapping.

OOS remains unopened by design.
Frozen OOS remains unopened by design.

The final E032 outcome is one of:

- NO_CANDIDATE_ZONE
- CANDIDATE_ZONES_FOUND

Neither outcome changes the production/research state machine.

Any candidate zone must be converted into an exact causal trigger only in a new pre-registered experiment.
