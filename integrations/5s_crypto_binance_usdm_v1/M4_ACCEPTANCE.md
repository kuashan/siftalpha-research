# M4 — 恢复、对账与联合真机验收

状态：**IMPLEMENTED_AWAITING_DEVICE_ACCEPTANCE**

M4 的开发边界已经完成，和 M3 一起交付真机验收。

实现内容：
- API 凭据仍只保存在当前 Python 进程内；重启后需要用户重新连接 Demo。
- 重新连接成功后，自动执行 M4 Recovery（恢复对账），未通过前自动交易门禁关闭。
- 每个币种独立对账，某一个币种异常不会阻止其他已经通过对账的币种。
- 本地 SQLite 已成交订单账本与 Binance Demo 当前持仓数量强一致校验。
- 如果程序在订单提交后、状态落库前崩溃，重启后用固定 clientOrderId 查询 Binance 并恢复订单状态。
- 本策略遗留未成交订单会自动取消；非本策略订单不会擅自取消，而是阻止对应币种自动交易。
- 发现空头、未知外部仓位、订单账本/远端持仓不一致时进入 RECOVERY_BLOCKED。
- 恢复成功后以当前最近一根已收盘 K 线重新建立 baseline，不追补停机期间已经错过的历史开盘成交。
- PnL、资金费、手续费重新从 Binance Demo 刷新。
- Web 提供“重新对账”“取消本策略挂单”“紧急平仓”三个独立控制。
- 紧急平仓只作用于选定币种，同时停止该币种策略；不会影响其他币种。
- 实盘仍然锁定。

真机联合验收（M3 + M4）：
1. 连接 Binance Demo，确认“恢复对账状态 = 全部对账通过”或每个启用币种已通过。
2. 启动任意一个币种，确认状态进入“监测中”。
3. 验证四币可使用不同资金、杠杆、周期独立启停。
4. 保持项目运行，等待真实冻结信号；产生信号后验证 Demo 自动 MARKET 成交、仓位比例和 PnL。
5. 在有策略状态后停止/重启 SiftAlpha 项目，重新输入 Demo API；确认自动对账后没有重复订单。
6. 使用“重新对账”确认不改变正确仓位。
7. 如需主动测试安全出口，可用小额 Demo 仓位测试“紧急平仓”；它应只停止并平掉当前币种。
8. Binance Demo 中不得出现实盘订单；LIVE 入口不存在。

通过以上真机验收后：
- M3 = CLOSED
- M4 = CLOSED
- 本轮开发正式结束。
