# 5s ARM64 Image M2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Add a reproducible, image-only ARM64 deployment package for the existing 5s strategy without changing strategy or trading behavior.

**Architecture:** Keep `integrations/5s_crypto_binance_usdm_v1` as the application source. Add a deployment-only entrypoint, Dockerfile, and Compose file under `deployment/5s-independent-server-module/`; build and publish the image from GitHub Actions to GHCR with an immutable commit tag and digest. Oracle is not touched in M2.

**Tech Stack:** Python 3.11, Docker Buildx, GitHub Actions, GHCR, Docker Compose.

**Spec:** `deployment/5s-independent-server-module-M1-audit.md`

## Global Constraints

- Do not modify `engine/`, `strategy/`, `exchange/`, `app.py`, or existing trading routes.
- Preserve PAPER/DEMO/TESTNET selection and existing Binance Demo credential paths.
- The container listens on port 8080 internally; Compose must not publish a host port.
- Persist only the module's database/configuration state under `/data`.
- GitHub Actions is the only formal build environment; Oracle is not accessed or changed.
- The image must target `linux/arm64` and be referenced by immutable commit tag/digest.
- Do not include credentials, databases, logs, trade records, or generated caches in the image source context.

## Review Focus

- Startup wrapper must call the existing app entrypoint without changing strategy initialization.
- Missing credentials must not be written into source or workflow files.
- Compose must expose 8080 internally without a `ports:` host binding.
- Runtime writes must resolve to `/data/5s_crypto_v1.db`.
- Build context must restore the generated SSSS index and chart vendor before image build.
